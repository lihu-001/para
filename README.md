# PARA

Personal AI Reimbursement Assistant：本地优先的个人支出、发票与报销账本。

## 启动

要求 Node.js 20+、Python 3.11+。

```bash
npm install
python -m pip install -r backend/requirements.txt
python -m uvicorn backend.main:app --reload
```

另开终端：

```bash
npm run dev
```

访问 <http://127.0.0.1:5173>。开发服务器将 `/api` 代理到 <http://127.0.0.1:8000>。API 文档：<http://127.0.0.1:8000/docs>。
页面顶部显示“工作台 / 当前页面”的路径；当前日期显示在左侧“个人工作区”下方。

数据存储于 `data/para.sqlite3`，PDF/图片原件存储于 `data/invoices/`。上传发票后，PDF 每页先渲染为图片；图片及 PDF 页面均由多模态大模型解析，解析并记录购买方、销售方的公司名称和税号，用户核对金额、日期、购销方信息后确认入账。此过程会将发票内容发送至配置的 API 服务商；未配置 API Key 时解析会提示配置错误。金额以整数分存储；“支出”页面与仪表盘中的支出台账按每页 10 笔从后端查询，支持按商户、类别或报销状态（中文名）搜索及翻页。“发票”页面以分页 table 展示发票号码、开票日期、开票金额、购买方信息和销售方信息，支持按号码、购销方名称或税号搜索。点击发票行的“删除”并确认后删除发票；已关联支出的发票会解除关联，原件一并删除。
删除支出时使用页面内确认弹窗展示商户、日期、金额及已关联发票的处理说明；只有点击“确认删除”才会提交删除请求。
仪表盘“无发票金额”按每笔支出计算未关联发票的余额，已到账（`PAID`）支出不计入此汇总；支出台账仍显示每笔支出实际未关联的金额。
报销状态有“无需报销”“未提交”“已提交”“已到账”四种；新支出默认为“已提交”。首次启动时将已有的“已提交”记录一次性迁移为“未提交”，之后手动设为“已提交”的记录不会在重启时被覆盖。旧数据的“待提交、审核中、已退回、已批准”归入“已提交”，“已取消”归入“无需报销”；仪表盘“已提交”只统计已提交的支出。
支出台账的报销状态默认以中文标签展示；点击标签选择新状态，再点击页面其他位置（使选择框失焦）自动保存。未修改时不会提交；保存失败会保持原状态并在该行显示错误，也可以通过行内“修改”弹窗编辑其他字段。



## Agent 对话模式

点击页面右上角“对话”按钮，在右侧打开 Agent 对话面板。面板内可切换已保存的服务商模型；切换只影响之后发送的消息，不清空当前对话或更改发票解析的默认模型。Agent 使用“AI 设置”中配置的 OpenAI-compatible 服务商，通过受限工具访问 PARA 业务接口：支出、发票和汇总查询必须调用对应系统工具；用户明确要求将附件记录导入、录入、存入或入账时，Agent 会强制选择批量导入工具，不允许只回复说明而不执行工具调用。查询不会执行任意 SQL；新增支出、批量导入、发票关联等写入操作只会生成待确认预览，必须点击“确认执行”后才写入数据库。若模型没有实际调用工具，系统会返回失败，不会把未执行误报为已执行。用户提供文件、图片或文本时，模型根据内容和意图选择合适的工具，将能明确映射为系统支出字段的数据生成待确认预览，不依赖固定文件名或固定格式。多条支出可批量准备；缺失日期可在预览中补充，其他关键字段不明确时由 Agent 询问用户。
对话输入框支持选择文件或在输入框内使用 Ctrl+V 粘贴图片，一次最多 5 个文件，每个文件最大 20 MB；支持 PNG/JPEG/WebP 图片、PDF 和文本文件。图片会以多模态输入发送给模型，PDF/文本会先提取文字；原文件保存在 `data/agent_uploads/`，消息中显示附件并可下载。附件元数据、对话、工具调用、工具参数和工具结果保存在本地 SQLite 中，便于恢复上下文和审计。当前工具调用要求模型服务商支持 OpenAI-compatible `tools` / function calling；如果服务商只支持普通 Chat Completions，发票解析仍可用，但 Agent 对话会明确提示未完成工具调用。Agent 只读取当前本地账本，不会自动删除数据、修改已有金额、改变报销状态或提交报销。
Agent 对话列表支持删除对话。删除会同时删除该对话的消息、待确认操作和附件原件，不影响支出、发票等业务账本数据；操作前需要在界面确认。

AI 配置在网页端完成：打开左侧“AI 设置”，填写服务商的 API Base URL 和 API Key；“拉取模型”从服务商的 OpenAI-compatible `/models` 接口读取列表，模型名称下拉框选择发票解析的默认模型。然后点击“测试连接”，测试成功后保存配置及模型列表。已经保存的同一服务商可留空 API Key 继续拉取，换服务商时必须提供新密钥。输入框右侧的眼睛按钮仅显示或隐藏当前输入的 Key，不会读取已保存的 Key。API Key 仅保存在本地 `data/para.sqlite3`，接口不会返回完整密钥。旧配置尚未拉取模型时，保存的默认模型仍可用于发票解析和对话；服务商不提供 `/models` 时无法取得多个可切换模型。

选择支持图片输入和 JSON 响应的 OpenAI-compatible 多模态模型。默认保留 PDF/图片原件用于报销复核；也可以在页面中选择“确认后删除”。上传发票和 Agent 对话内容会发送至配置的模型服务商，请根据隐私要求选择服务商。报销状态目前只能在台账中手动修改，尚未实现状态流转校验和状态变更历史；也不支持用户认证和发票验真。不要将无认证 API 直接暴露到公网。

## 代码结构

- `src/App.tsx`：页面组合、组件与页面状态。
- `src/domain.ts`：前端领域类型、状态常量、格式化与 API 请求辅助函数。
- `backend/main.py`：FastAPI 路由、请求模型和 HTTP 编排。
- `backend/services.py`：支出、发票、关联和汇总等业务操作。
- `backend/database.py`：SQLite 连接、表结构初始化和兼容性迁移。

以上拆分只调整代码职责边界，不改变现有 API、数据库字段或业务流程。
